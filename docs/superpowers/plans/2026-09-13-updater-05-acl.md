# Updater Phase 4 — Headscale Access Policy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Headscale's allow-all default with a policy where only `tag:server` (`gcp-updater`) may reach players, and only on adb port 5555 — so a leaked fleet key, or anyone who joins the tailnet, can reach nothing.

**Architecture:** Headscale v0.29.3 reads a HuJSON policy file when `policy.mode: file` and `policy.path` points at it. Today `path: ""` means no policy and every node can reach every node. This plan tags the one untagged player, writes and validates the policy, points the config at it, restarts, and proves the update path still works.

**Tech Stack:** Headscale v0.29.3 (systemd `headscale serve` on GCE VM `headscale`), HuJSON, gcloud.

**Spec:** `docs/superpowers/specs/2026-09-13-updater-app-design.md` §13

## Global Constraints

- `tagOwners` owners must be written as **`markai@`** — verified on the live server 2026-09-13: `markai@` → `Policy is valid`; `markai` → `invalid owner format`.
- **Never** leave `gcp-updater` unable to reach a player. Tag `ohm` before the policy goes live; verify reachability after.
- Tagging a node must **not** change its IP. Record every node's IP before, compare after.
- Back up `/etc/headscale/config.yaml` before editing; keep the rollback in Task 6 ready.
- A `policy.path` change needs a full `systemctl restart headscale` (the unit's `ExecReload` HUP reloads policy *content*, not config). Expect clients to drop and reconnect within ~30 s.
- This plan is safe to run before or after the Phase 0 spike: `tag:server` → `tag:player:5555` stays allowed, and the spike node joins as `tag:player`.
- Task 4's `sed` anchor was **dry-run on a copy of the live config on 2026-09-13**: exactly one line
  changed (line 299, `path: ""` → `path: /etc/headscale/policy.hujson`); the database path (line 219)
  was untouched; the copy was removed and the real file left unchanged.
- Not in scope: an admin laptop tag. A laptop joined with the fleet key is `tag:player` and will reach nothing — by design.

Shorthand (run from the laptop). A **function, not a string variable** — zsh does not
word-split an unquoted `$VAR`. Keep-alive flags stop a stalled IAP tunnel hanging.

```bash
vmssh() { gcloud compute ssh headscale --project markai-499512 --zone us-central1-a --tunnel-through-iap --ssh-flag=-oServerAliveInterval=10 --ssh-flag=-oServerAliveCountMax=3 --command "$1"; }
```

### Task 3: Write and validate the policy file

**Files:**
- Create (on the VM): `/etc/headscale/policy.hujson`

**Interfaces:**
- Produces: a policy file Headscale reports as valid.

- [ ] **Step 1: Write the policy**

```bash
vmssh 'sudo tee /etc/headscale/policy.hujson >/dev/null <<"EOF"
{
  // Mark AI fleet access policy.
  //
  // Default is DENY: anything not accepted below is dropped.
  //
  // tag:server  = gcp-updater, the only machine that pushes installs into boxes.
  // tag:player  = every screen. A player may reach nothing, and nothing but the
  //               updater may reach a player, and only on adb (5555). A copy of the
  //               fleet join key therefore yields a node that can talk to no one.
  "tagOwners": {
    "tag:server": ["markai@"],
    "tag:player": ["markai@"],
  },
  "acls": [
    { "action": "accept", "src": ["tag:server"], "dst": ["tag:player:5555"] },
  ],
}
EOF
sudo chmod 644 /etc/headscale/policy.hujson && sudo ls -l /etc/headscale/policy.hujson'
```
Expected: the file is listed, mode `-rw-r--r--`.

- [ ] **Step 2: Validate it**

```bash
vmssh 'sudo headscale policy check -f /etc/headscale/policy.hujson'
```
Expected: `Policy is valid`. Any other output → stop; fix the file; do not continue to Task 4.

### Task 4: Point Headscale at the policy and restart

**Files:**
- Modify (on the VM): `/etc/headscale/config.yaml` — the `policy:` block's `path`

**Interfaces:**
- Consumes: the valid `/etc/headscale/policy.hujson` (Task 3).

- [ ] **Step 1: Set `path` inside the `policy:` block only**

`path:` also appears elsewhere in the config (the database path), so the edit is scoped to the lines between `policy:` and the next top-level key.

```bash
vmssh 'sudo sed -i "/^policy:/,/^[a-z_]*:/ s|^  path: \"\"$|  path: /etc/headscale/policy.hujson|" /etc/headscale/config.yaml
sudo sed -n "/^policy:/,/^[a-z_]*:/p" /etc/headscale/config.yaml | grep -E "mode:|path:"'
```
Expected exactly:
```
  mode: file
  path: /etc/headscale/policy.hujson
```
If `path:` still shows `""`, the anchor did not match — stop and inspect the block before restarting.

- [ ] **Step 2: Confirm the database path was not touched**

```bash
vmssh 'diff <(sudo grep -n "db.sqlite" /etc/headscale/config.yaml.pre-acl) <(sudo grep -n "db.sqlite" /etc/headscale/config.yaml) && echo "db path unchanged"'
```
Expected: `db path unchanged`

- [ ] **Step 3: Restart and confirm it came up**

```bash
vmssh 'sudo systemctl restart headscale; sleep 5; systemctl is-active headscale; sudo journalctl -u headscale --since "1 min ago" --no-pager | grep -iE "policy|error|fatal" | tail -5'
```
Expected: `active`; no `fatal`; any `policy` log line refers to the new file without an error.

- [ ] **Step 4: Headscale reports the policy it is enforcing**

```bash
vmssh 'sudo headscale policy get'
```
Expected: the JSON of Task 3's policy (comments stripped).
